# Цели активных проб контура

Здесь лежит `ingress.json` — цель внешней пробы готовности. Файл **генерируется при подъёме
контура** из `.env` и не коммитится: в нём публичное имя конкретной установки.

```bash
printf '[{"targets":["https://%s/health/ready"]}]\n' "$TESTAPP_PUBLIC_HOST" \
  > deploy/staging/targets/ingress.json
```

Порядок целиком — `docs/OPERATIONS.md` §16.0.1.

## Почему отдельный файл, а не строка в prometheus.yml

Prometheus не подставляет переменные окружения в `scrape_configs`, а публичное имя у каждой
установки своё. Правка смонтированного конфига руками привела бы к тому, что развёрнутый файл
разошёлся бы с репозиторием — ровно то, что `PrometheusConfigTests` не даёт делать.
`file_sd_configs` оставляет конфиг неизменным и выносит различие в один генерируемый файл.

## Почему отсутствие файла — это алерт

Prometheus стартует и без него: job просто останется без целей. Внешняя проба при этом
молчит, и молчание неотличимо от благополучия — тот же класс отказа, ради которого
существует `TestAppReadinessProbeUnreachable`. Поэтому `deploy/staging/alerts-ingress.yml`
содержит правило на `absent(up{job="testapp-ingress"})`: пустой job виден как авария
наблюдаемости, а не как её отсутствие.
